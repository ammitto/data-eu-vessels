= Ammitto EU vessel sanctions data

image:https://github.com/ammitto/data-eu-vessels/actions/workflows/fetch.yml/badge.svg["Fetch Data", link="https://github.com/ammitto/data-eu-vessels/actions/workflows/fetch.yml"]

This repository stores EU-designated vessel records as YAML for Ammitto,
using the list published by the Danish Maritime Authority (DMA).
`processed/` holds one file per vessel.

== Source

* Publisher: Danish Maritime Authority (DMA)
* List page: https://www.dma.dk/growth-and-framework-conditions/maritime-sanctions/general-information/eu-vessel-designations
* File downloaded: the "List of designated vessels" spreadsheet (`.xlsx`) linked from that page; its URL changes with each new version

The page and its spreadsheet cover vessels designated under Annex XLII of
Council Regulation (EU) 833/2014 (sanctions against Russia and Belarus) and
under Council Regulation (EU) 2017/1509 (sanctions against North Korea). The DMA notes that vessels can change names,
so a vessel should be checked by its IMO number.

== Contents

`processed/` holds one file per vessel, named after its IMO number:
`processed/eu-vessel-1021570.yaml` is IMO 1021570. A vessel listed without an
IMO number is named after the vessel name instead, such as
`processed/eu-vessel-min-ning-de-you-078.yaml`.

`processed/_index.yaml` lists every file, with the time of the last fetch.

[cols="1,1,3"]
|===
| Key | Type | Meaning

| `vessel_name` | string | Name of the vessel
| `imo_number` | string | IMO number, where listed
| `designations` | list | One entry per designation: `subject_to` (the measure and regulation, such as `Article 3s (Council Regulation 833/2014)` or `Asset freeze (Council Regulation 2017/1509)`) and `date_of_application` (`YYYY-MM-DD`)
|===

== Using the data

Clone or download this repository and run either example from its root
directory.

Ruby:

[source,ruby]
----
require "yaml"

Dir.glob("processed/eu-vessel-*.yaml").sort.each do |path|
  vessel = YAML.safe_load_file(path)
  measures = vessel["designations"].map { |d| d["subject_to"] }.join("; ")
  puts [vessel["imo_number"], vessel["vessel_name"], measures].join("\t")
end
----

Python (requires PyYAML, installed with `python3 -m pip install PyYAML`):

[source,python]
----
import glob
import yaml

for path in sorted(glob.glob("processed/eu-vessel-*.yaml")):
    with open(path, encoding="utf-8") as f:
        vessel = yaml.safe_load(f)
    measures = "; ".join(d["subject_to"] for d in vessel["designations"])
    print(vessel.get("imo_number", ""), vessel["vessel_name"], measures, sep="\t")
----

The same list, harmonized with the other sources into JSON-LD:
https://www.ammitto.org/api/v1/sources/eu_vessels.jsonld

== Harmonized field mapping

The https://github.com/ammitto/ammitto/blob/main/lib/ammitto/sources/eu_vessels/transformer.rb[eu_vessels transformer]
maps the processed source fields below to canonical Ruby attributes.
Entity classes are in `Ammitto::Ontology::Entities`, entry/regime classes in
`Ammitto::Ontology::Sanction`, and nested values in
`Ammitto::Ontology::ValueObjects`. JSON-LD serialization can use different keys.

[cols="2,2,4",options="header"]
|===
| Source fields | Canonical target | Transformation

| `imo_number`, `vessel_name`
| `VesselEntity.id`, `SanctionEntry.entity_id`
| Use the IMO number as the local ID, or a name slug when it is absent; scope the IRI to this source.

| `vessel_name`
| `VesselEntity.names` (`NameVariant.full_name`)
| Create a primary name when supplied.

| `imo_number`
| `VesselEntity.imo_number`, `source_references` (`SourceReference.reference_number`)
| Retain the IMO value; the source reference also records `source_code` and the harmonization time in `fetched_at`.

| `designations`
| One `SanctionEntry` per designation
| Share one vessel entity. Sort multiple designations by date/measure; the earliest keeps the unsuffixed entry ID, later IDs include date and measure.

| `designations[].date_of_application`
| `TemporalPeriod.listed_date`, `is_indefinite`
| Retain the designation date and mark the period indefinite. Older top-level `date_of_application` records are also accepted.

| `designations[].subject_to`
| `SanctionEntry.regime`, `legal_bases`, `effects`
| Parse the stated regulation and measures. Article 3s maps to entry and service prohibitions; unknown measures stop transformation.

| `designations[].subject_to`
| `SanctionEntry.remarks`
| Retain the original measure text. A legacy designation without this field supplies no inferred regime or measure.

|===

== Updates

The `Fetch Data` workflow (`.github/workflows/fetch.yml`) downloads the list
every day at 06:00 UTC and commits any change to `processed/`. It runs with
`--prune`, so a vessel the DMA has removed is deleted here on the next fetch.

== Development

`processed/` is generated by the Ammitto gem. To refresh it locally, use
Ruby 3.4 (the version selected by the fetch workflow) and Bundler. From
the repository root, run:

[source,shell]
----
bundle install
bundle exec ammitto fetch eu_vessels --format yaml --output-dir processed --verbose --prune
----

`--prune` removes files for listings no longer present in the fetched list.
Review the generated changes before committing them.

Fetch and parser changes belong in the
https://github.com/ammitto/ammitto[Ammitto gem]; its source models are in
https://github.com/ammitto/ammitto/tree/main/lib/ammitto/sources/eu_vessels[`lib/ammitto/sources/eu_vessels/`].
Report data or source-list issues in
https://github.com/ammitto/data-eu-vessels/issues[this repository].
